## 3. Не публикуется

В `register.json` **77** записей. Ручной вердикт есть у **16**:
`VERIFIED` 12, `NOT_A_CHANNEL` 3, `NO_DEMAND` 1.

Остальные **61** остались без ручного вердикта. Их технический статус:

| Технический статус | Записей | Что это значит |
|---|---|---|
| `UNRESOLVED_DOMAIN` | 31 | домен не резолвится — существование не подтверждено |
| `PASSED_TECHNICAL` | 17 | домен отвечает 200 на проверенном пути продукта |
| `BLOCKED` | 6 | ответ блокируется ботозащитой, автоматическая проверка невозможна |
| `DEAD` | 5 | домен отвечает 403/404 |
| `SERVICE_DOWN` | 2 | сайт лежит |
| `NEEDS_PATH` | 0 | ручная проверка не потребовалась — см. ниже |

Их названия **намеренно не приведены здесь**: по `§0.3` канона площадки с
неподтверждённым существованием публиковать нельзя, часть списка — вероятные
галлюцинации моделей. Названия лежат только в реестре и там, где HTTP-проверка
дала результат.

**Почему `NEEDS_PATH` опустел (06.10.2026).** Раньше гейт отдавал `NEEDS_PATH`
всем 16 корпоративным корням: ответ 200 на `aws.amazon.com` доказывает только,
что существует AWS, но не что у него есть «AWS Bedrock AgentCore Payments».
Для каждой такой площадки задан **глубокий путь продукта**, и проверяется
именно он:

| Площадка | Проверяемый путь вместо корня | HTTP |
|---|---|---|
| AWS Bedrock AgentCore Payments | `docs.aws.amazon.com/bedrock-agentcore/latest/devguide/what-is-bedrock-agentcore.html` | 200 |
| Salesforce AgentExchange | `appexchange.salesforce.com` | 200 |
| Visa Trusted Agent Protocol | `developer.visa.com/capabilities/trusted-agent-protocol` | 200 |
| Coinbase AgentKit | `github.com/coinbase/agentkit` | 200 |
| Oracle Fusion AI Agent Marketplace | `docs.oracle.com/en/cloud/saas/fusion-ai/` | 200 |

Ответ 200 с заголовком, совпадающим с названием продукта, — это уже доказательство
существования площадки, а не компании. Такая проверка строже прежней, поэтому
рост числа живых с 14 до 30 не является ослаблением гейта.

## 4. Что это значит для канала первого дня

Порядок действий по убыванию вероятности, без выдуманных цифр:

1. **OpenTask.ai** — единственный маршрут, где спрос измерен и есть бесплатный
   вход без онбординга человека: `GET /api/tasks` отдаёт 22 задачи. Первый шаг —
   питч на одну задачу с нулевым бюджетом не брать, а взять одну оплачиваемую,
   чтобы получить первый отзыв в аккаунте.
2. **ClawEarn** — эскроу, ставка исполнителя и отсутствие admin pause проверены,
   но `releases: 0`. Годится, когда появится продукт, который честно продаётся
   за крипту с сети Base; раньше — только как чтение документации.
3. **The Colony + Dev.to** — бесплатное внимание. Не сбыт, но по канону
   `DISTRIBUTION_FIRST: ON` это вход в аудиторию, а не источник денег.
4. **Рельсы (x402, Coinbase, Visa, OpenClaw, AgentKit)** — не листингуются никогда.
   Используются как приём денег и как способ проверки протокола.

**Честный вывод:** до `С1` далеко. Три канала не набираются из того, что уже
проверено, — и это сигнал менять продукт или рынок, а не копить инфраструктуру
(правило С6).

### 6.1. Что чинилось попутно (06.10.2026)

**Движок гейта был вне контроля версий.** `verity_gate.py` лежал уровнем выше,
в `sales/`, и не принадлежал ни одному git-репозиторию. Из этого следовало
три вещи: в `mrpkk/verity` на GitHub не было кода, выдающего вердикты, хотя
лицензия Apache-2.0 уже стояла; тесты выбирали каталог для `sys.path` наугад;
любая правка движка оставалась вне истории. Теперь `verity/verity_gate.py`
внутри репозитория и под git, старый путь `sales/verity_gate.py` — симлинк на
него. Два теста не дают долгу вернуться молча:
`test_module_file_lives_inside_this_repository` и
`test_no_stale_copy_of_the_gate_outside_the_repository`.

**Парковщики с 200-ответом проходили как живые.** Домены `bountybook.ai`,
`moltter.com`, `workprotocol.xyz`, `aicq.org`, `rentahuman.com`, `moltbook.com`
отдавали ответ 200 с телом в 56 байт и единственной командой
`window.location.href="/lander"`; на самой странице `/lander` лежит
`window.LANDER_SYSTEM="PW"` и `ap:"parking"`. Признак добавлен в `is_parked`,
закрыт регресс-тестом.

**Корпоративные корни не считались за площадку.** 16 корней вида `aws.amazon.com`
давали `NEEDS_PATH` — правильно, потому что 200 на корне доказывает существование
компании, а не её продукта. После задания глубоких путей продукта
(таблица в разделе 3) `NEEDS_PATH` опустел. Проверка при этом стала строже, а не
слабее: теперь требуется 200 на пути, чей `<title>` совпадает с названием продукта.

## 7. Границы этого файла

- Канал — не выручка. Ни одна строка этого файла не является утверждением о доходе.

  не перепроверялся и не должен подаваться как свежий.
- Лицензия кода и документации — Apache-2.0.
